# triage-mvp — предварительный опрос пациента

Тренировка деплоя: от пустого репозитория до публичной ссылки.

## Что умеет

- **US-1** — текстовый диалог из 7 вопросов, состояние хранится на сервере (`lib/store.js`), у клиента только `sessionId`.
- **US-2** — ответы превращаются в структурированную карточку: жалобы, длительность, боль 0–10, аллергии, хронические заболевания, препараты + черновик записи в свободной форме.
- **US-3** — тревожные признаки и одна из четырёх категорий срочности (самопомощь / плановый приём / сегодня / неотложно). На «неотложно» — баннер с номером 103.
- **US-4** — `/doctor.html`: очередь, отсортированная по срочности, кнопка «Скопировать запись».
- **US-0** — `DEMO_MODE=1` (значение по умолчанию) проигрывает записанные ответы модели из `lib/fixtures.js`, ключ к API не нужен.

Категория срочности считается правилами (`lib/triage.js`), а не моделью — результат воспроизводим в обоих режимах.

## Запуск локально

```bash
npm install
npm start          # http://localhost:3000
npm run smoke      # прогон трёх сценариев по HTTP + проверка сортировки очереди
```

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DEMO_MODE` | `1` | `1` — записанные ответы модели, ключ не нужен. `0` — живые вызовы API. |
| `ANTHROPIC_API_KEY` | — | Нужен только при `DEMO_MODE=0`. |
| `DOCTOR_PASSWORD` | — | Если задан, очередь врача открывается только по `/doctor.html?key=<значение>`. |
| `PORT` | `3000` | Render подставляет свой. |

## Деплой на Render

1. Запушить репозиторий на GitHub.
2. Render → New → Web Service → выбрать репозиторий. `render.yaml` подхватывается сам (Blueprint), иначе вручную: Build `npm install`, Start `npm start`, env `DEMO_MODE=1`.
3. Открыть выданный `https://<имя>.onrender.com` — и с ноутбука, и с телефона.

Бесплатный инстанс засыпает после 15 минут простоя: первый запрос после сна идёт ~30 секунд. Перед демонстрацией открыть ссылку заранее.

## Чего здесь нет и не будет

Красивого интерфейса, голосового ввода, ролей и админки, интеграций с медицинскими ИС, реальных персональных данных. Это MVP под критерии приёмки, не продукт.
