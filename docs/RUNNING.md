# Локальный запуск

Проект состоит из трёх независимых сервисов. Каждый запускается своей командой,
в своём терминале.

```
браузер → web    :3000   Next.js — страницы и прокси к API
         → api    :3001   Node + Express — диалог, карточка, очередь
         → rules  :8000   Python + FastAPI — срочность, длительность, сводка
```

Публичный адрес — это `web`. Остальные два ему служат и наружу не смотрят.

## Что нужно поставить

| | Версия | Проверить |
|---|---|---|
| Node.js | 20 или новее | `node -v` |
| Python | 3.11–3.12 | `python --version` |
| npm | идёт с Node | `npm -v` |

Про Python: локально всё работает и на 3.13/3.14, но у `pydantic` под самые
свежие версии может не быть готового колеса — тогда `pip install` уйдёт
собирать Rust-ядро из исходников и упадёт. На 3.12 такого не бывает. На
сервере версия зафиксирована файлом `rules/.python-version`.

## Установка

```bash
git clone https://github.com/logreus-cloud/triage-mvp.git
cd triage-mvp

npm run install:all                      # то же, что npm install в api и web
pip install -r rules/requirements.txt
```

Ключ к API не нужен: по умолчанию включён демонстрационный режим.

## Запуск: три терминала

**Терминал 1 — правила (Python):**

```bash
cd rules
python -m uvicorn app:app --port 8000
```

**Терминал 2 — API (Node):**

```bash
cd api
RULES_URL=127.0.0.1:8000 PORT=3001 npm start
```

**Терминал 3 — фронтенд (Next.js):**

```bash
cd web
API_URL=127.0.0.1:3001 npm run dev
```

Открыть **http://localhost:3000**.

> **Пишите `127.0.0.1`, а не `localhost`.** На Windows разрешение `localhost`
> сначала пробует IPv6 и добавляет к каждому запросу секунды. Мы на этом
> потеряли время, решив, что тормозит код.

### Windows: PowerShell и cmd

Синтаксис `VAR=значение команда` работает в Git Bash и в Unix-оболочках.
В PowerShell переменные задаются отдельно:

```powershell
$env:RULES_URL="127.0.0.1:8000"; $env:PORT="3001"; npm start
```

Ещё одно: npm выполняет скрипты через `cmd`, а не через `sh`, поэтому
подстановки вида `${PORT:-3000}` внутри `package.json` не разворачиваются.
Если добавляете скрипт — не рассчитывайте на них.

## Проверка, что всё поднялось

```bash
curl http://127.0.0.1:8000/health          # {"ok":true,"service":"rules",...}
curl http://127.0.0.1:3001/api/health      # {"ok":true,"service":"api",...}
curl http://127.0.0.1:3000/api/health      # то же самое, но через прокси фронтенда
```

Третья команда — самая полезная: она проходит по всей цепочке. В её ответе
смотрите на поле `rules`:

```json
"rules": { "configured": true, "url": "http://127.0.0.1:8000", "lastError": null }
```

`lastError: null` означает, что API достучался до правил.

## Команды проверки

Запускаются из корня репозитория.

```bash
npm run smoke        # сквозной прогон 5 сценариев по всем трём сервисам
npm run test:rules   # 24 теста на правила (pytest)
npm run seed         # наполнить очередь врача демо-данными
npm run wake         # разбудить уснувшие инстансы (нужно только на сервере)
```

В выводе `smoke` есть колонка «движок». Должно быть `python`. Если там
`js-fallback` — API не видит сервис правил, и категории считаются упрощённо.

Все скрипты принимают `BASE_URL`, поэтому тот же прогон идёт по любому адресу:

```bash
BASE_URL=https://triage-web-eaj2.onrender.com npm run smoke
```

## Переменные окружения

Полный список — в `.env.example`. Коротко:

| Переменная | Где | По умолчанию | Смысл |
|---|---|---|---|
| `DEMO_MODE` | api | `1` | `1` — записанные ответы модели, ключ не нужен |
| `ANTHROPIC_API_KEY` | api | — | нужен только при `DEMO_MODE=0` |
| `RULES_URL` | api | не задан | адрес сервиса правил; не задан — работают резервные JS-правила |
| `API_URL` | web | `127.0.0.1:3001` | адрес API для прокси |
| `DOCTOR_PASSWORD` | api | — | если задан, очередь врача открывается только по `?key=...` |

Схему (`http://`) в `RULES_URL` и `API_URL` писать не обязательно — код
достраивает её сам, различая внутренний адрес от публичного по точке в имени
хоста.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| В карточках `движок: js-fallback` | API не видит правила | Проверьте, что терминал 1 жив и `RULES_URL` указывает на 8000 |
| `API недоступен` на странице | Не запущен api | Проверьте терминал 2 и `API_URL` |
| Всё отвечает за секунды | Разрешение `localhost` через IPv6 | Замените `localhost` на `127.0.0.1` |
| `pip install` падает на `pydantic-core` | Нет готового колеса под вашу версию Python | Поставьте Python 3.12 |
| Порт занят | Остался процесс с прошлого раза | Windows: `taskkill /F /IM node.exe`, `taskkill /F /IM python.exe` |
| Правки не видны | Запущена собранная версия | В `web` используйте `npm run dev`, а не `npm start` |

## Разработка

`npm run dev` в `web` пересобирает страницы на лету. Сервисы `api` и `rules`
перезапускать надо руками; для правил удобно добавить `--reload`:

```bash
python -m uvicorn app:app --port 8000 --reload
```

Состояние диалогов и очередь врача живут в памяти процесса `api` —
после его перезапуска очередь пустая. Наполнить заново: `npm run seed`.
